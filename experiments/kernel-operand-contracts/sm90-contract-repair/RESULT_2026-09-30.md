# SM90 block-FP8 contract repair: minimal-extension result

Status: selected-path repair validated with revised builder R2 (a build-tool
deviation); partial completion, further execution stopped; K5 not funded.
The Chinese companion is authoritative. Publication contains only source,
tests and summarized evidence; raw host logs and binaries stay private.

## Stage summary

Problem: the SM90 blockwise branch interprets operands as e4m3 and scales as
packed column-major layouts, but lacked corresponding boundary checks.
Reproduction: pinned base/fix minimal extensions, real CUDA kernels, positive
and negative controls, one fresh process per case. Root cause: dispatch uses
fixed element types/layouts while the entry admitted inconsistent metadata.
Repair: four SM90-local guards before output-dtype and swapped dispatch;
equivalent singleton strides remain accepted. Validation: base 27 matches plus
three planned skips; fix 30 matches, no unscored cases. The result is a local
correctness repair and regression artifact, not a speedup or demonstrated
production incident. Full serving, overhead and independent use remain gaps.

Post-run local publication checks: 24 passed and three dependency skips across
the SM90 CPU suites; Ruff check/format passed. The new tensor-allocation test
requires CPU Torch and was not run locally. Historical H800 preflight completed
the original 21 CPU checks without skips; it did not run the later new test.
Publication review used an isolated clean HEAD plus these eight new files:
464 unit tests completed (six skips), 28 engine-binding CPU controls passed,
Ruff check/format and compileall passed. This local check used Python 3.14;
the remote CI matrix remains a separate result.
