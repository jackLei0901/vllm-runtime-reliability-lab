# B2/B0 H800 protocol: blockwise operand dtype and operand strides

Status: frozen before the run once committed; nothing here has run. Chinese text not yet written. Inventory: [QUANT_GEMM_OPERAND_CONTRACT_INVENTORY_2026-09-29](../../docs/kernel/QUANT_GEMM_OPERAND_CONTRACT_INVENTORY_2026-09-29.md).

## Questions

- **B2 (new question).** Does the SM90 blockwise branch of `cutlass_scaled_mm` accept operand dtypes other than FP8 e4m3 without an error? Source reading finds no `a`/`b` dtype check on that branch, while the SM90 standard path checks both. A B2 result is reportable as new evidence. It does not settle whether such inputs should be rejected; that is an API-contract question.
- **B0 (known, regression coverage).** Padded operand and output views on the same path: the already-reported #55534 class. This completes the Q6 blockwise padded-view negative-control vector. It is **not** a second new finding.
- Out of scope for this booking: the B1 matrix (its control is reused; its eight cases are not rerun), M3–M11, SM100/SM120.

## Procedure

1. Gates: file digests, anchor check, `--local` source check, environment record.
2. Collection: `pytest -p no:randomly --collect-only -q experiments/kernel-operand-contracts/test_blockwise_dtype_and_stride_sm90.py > collected.txt`. It must list exactly **16** cases.
3. First run, once, in collection order (`-p no:randomly`; no `-n`, `-x` or `-k`):

   ```bash
   KOC_RECEIPTS=b2_b0_receipts.jsonl pytest -p no:randomly -q -rA -o junit_family=xunit1 \
     experiments/kernel-operand-contracts/test_blockwise_dtype_and_stride_sm90.py \
     --junitxml=b2_b0.xml
   ```

4. The single rerun, only if the selector permits it (below). Then stop.

## Cases and per-case outcomes

Sixteen cases: eight case types, each at M = 256 (non-swapped kernel) and M = 258 (M % 4 ≠ 0, swapped kernel; dispatcher L210), with N = 512, K = 1024.

The scoring source is the JSONL receipt file; JUnit XML is kept as a secondary record. Each receipt is flushed and fsynced when written:

- `start`: written by the autouse fixture **before** any tensor or reference setup;
- `result`: written after the op returns or raises, with `outcome`, `rel_diff`, `error`, `cuda_usable_after`;
- `end`: written at fixture teardown, whether the case passed, failed or errored;
- `skipped_context_unusable`: written instead of `start` when an earlier case broke the CUDA context.

Numerical outcome, as implemented in the test: `correct` if `rel_diff` < 5e-3; `wrong` if `rel_diff` > 5e-2 or the output is non-finite; `ambiguous` otherwise; `raised` if the op throws an exception that the test catches and records.

| Case | Input | Prediction | `supported` | `refuted` | `unscored` |
| --- | --- | --- | --- | --- | --- |
| control | packed e4m3, required scale layouts (same as B1's control) | correct | — | — | apparatus check; see below |
| B2-a | e5m2 activations | wrong | `wrong` | `raised` or `correct` | `ambiguous` or no `result` |
| B2-b | e5m2 weights | wrong | `wrong` | `raised` or `correct` | `ambiguous` or no `result` |
| B2-c | int8 activations and weights | wrong | `wrong` | `raised` or `correct` | `ambiguous` or no `result` |
| B2-std | e5m2 activations with per-tensor scales (standard branch) | raised | `raised` | any other recorded outcome | no `result` |
| B0-a | A as a padded view, `stride(0) = K + 128` | wrong | `wrong` | `raised` or `correct` | `ambiguous` or no `result` |
| B0-b | B as a padded view, column stride `K + 128` | wrong | `wrong` | `raised` or `correct` | `ambiguous` or no `result` |
| B0-c | output as a padded view, `stride(0) = N + 128` | wrong | `wrong` | `raised` or `correct` | `ambiguous` or no `result` |

B2-std is the contrast for B2: the same wrong dtype sent through the op's standard branch. If it records anything other than `raised`, the S7 source reading is wrong, and B2 cannot be described as a difference between branches.

## Errors, aborts and `unscored`

Each collected case falls into exactly one class, determined from its receipts by `select_rerun.py`:

| Receipts | Class | Score | Rerun |
| --- | --- | --- | --- |
| `start`, `result` (and normally `end`) | scored | per the table above | never |
| `start` and `end`, no `result` | failed before a result (in-process setup or harness failure) | `unscored` | never |
| `start` only | aborted: the process died during this case, at any stage including setup | `unscored` | never |
| `skipped_context_unusable` | skipped after a broken CUDA context | `unscored` in the first run | permitted cause |
| none | never started | `unscored` in the first run | permitted cause only after a verified abort |

- **Caught exception:** the case scores `raised`. If the CUDA probe after it fails (`cuda_usable_after: false`), later cases write `skipped_context_unusable`.
- **Session `unscored`:** a file digest or gated source blob differs; vLLM fails to import; compute capability is not 9.0; the build lacks SM90 block-FP8; collection is not exactly 16; or the receipt file is missing or unparsable.
- **Shape `unscored`:** all cases at one M are `unscored` if that M's control does not record `correct`, in the first run or the rerun.

## The single permitted rerun

Eligibility is decided only by the selector, which accepts exactly two causes and fails closed on anything else:

- skipped after a broken context: requires exactly one `result` with `cuda_usable_after: false`, earlier in collection order than every skipped case;
- never started after a hard abort: requires exactly one aborted case, which must be the last case that started, earlier in collection order than every never-started case.

The selector exits with status 2 and prints nothing when the receipts do not prove a permitted cause. This covers: unstarted cases without an abort, a skip without an earlier broken context, more than one abort or breaking case, repeated or unknown receipt events, receipts for uncollected cases, and unreadable receipts. Cases that failed before a result, aborted, or broke the context are never selected.

```bash
python experiments/kernel-operand-contracts/select_rerun.py collected.txt b2_b0_receipts.jsonl > rerun.txt
status=$?
```

- **Status 2:** no rerun. The unscored cases stay unscored.
- **Status 0 and `rerun.txt` empty:** stop. **Do not invoke pytest**; with no node ids it would collect cases outside the permitted set.
- **Status 0 and `rerun.txt` non-empty:** run exactly those node ids, once, in a fresh process with separate outputs, and record `rerun.txt` with its SHA-256:

  ```bash
  if [ "$status" -eq 0 ] && [ -s rerun.txt ]; then
    KOC_RECEIPTS=b2_b0_rerun_receipts.jsonl pytest -p no:randomly -q -rA -o junit_family=xunit1 \
      $(cat rerun.txt) --junitxml=b2_b0_rerun.xml
  fi
  ```

A case's first `result` stands; no case with a `result` from the first run is ever rerun. The rerun's receipts are scored by the same rules. There is no second rerun.

## Limits

One H800 session, at most 90 minutes including environment setup. If the environment is not ready within 60 minutes, stop and record `unscored`. No configuration changes after the first run starts. Confirm afterwards in the provider console that billing has stopped.

B2 is reported as new evidence, supported or refuted, with the API-contract question left open. B0 is reported as regression coverage for #55534's class.
