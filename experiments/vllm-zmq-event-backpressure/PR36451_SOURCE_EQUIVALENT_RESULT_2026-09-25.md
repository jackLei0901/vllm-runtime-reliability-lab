# #36451 Python change-set on the current vLLM wheel

Date: 2026-09-25 (America/Los_Angeles). Status: **source-equivalent, DP=1 proof of concept; not exact PR-head validation**.

## Result

The four-cell audit passed on one RTX 4090. Applying #36451's health-IPC behavior to an isolated copy of the installed vLLM package changed the response to the #53859 EngineCore-loop stall from `/health` 200 to an application-level 503 after the configured 60-second deadline. Both injected requests completed after the event consumer was released. Normal controls returned 200. This upgrades the earlier test-plugin result to a test of the PR's Python **behavioral change set**, but it does not establish that commit `206f28dc3b33abc4d0425fce8d8e14b1ea9cd7e0` itself runs with its declared dependencies.

## What was run

The host had vLLM `0.29.1rc1.dev398+g6af44e288`, PyTorch `2.13.0+cu130`, an RTX 4090, and a locally cached BF16 Qwen3-4B-Instruct-2507 model. The server used `--enforce-eager`. An isolated copy of its `vllm` package was placed first on `PYTHONPATH`; the original virtual environment and model were not edited. The **only** test plugin loaded was the pre-existing Stage 1 ZMQ backpressure injector. `VLLM_HEALTH_CHECK_TIMEOUT` selected off (`0`) or on (`60`).

## Why this is not exact PR-head validation

An **exact-head** result must run the actual #36451 source commit, with a compatible installed binary and the commit's declared dependencies. The available wheel and Torch 2.13 installation are a later build; #36451's head declares Torch 2.11. The host had about 12 GB free on the data disk and no `nvcc` on `PATH`. Merely copying four Python additions into the later wheel cannot retroactively make the rest of its Python/native code, dependency graph, and tests identical to the PR head. We did not replace or delete existing environments to attempt that build.

Because the PR changes only Python files, this source-equivalent test is useful and cheap, but its claim is narrower: **the PR's DP=1 health-ping mechanism works against the current-wheel #53859 stall in this controlled setting**. It is not a CI substitute, an exact-head compatibility result, or proof of production-safe `/health` semantics.

## Remaining review gates

- Measure a distribution of health round-trip times while genuinely long EngineCore steps execute. Eager mode did not cover CUDA graph capture or first-request compilation.
- Test DP>1 semantics **in #36451 itself**. With an external load balancer, `DPAsyncMPClient` is per rank. With vLLM's internal load balancer, `DPLBAsyncMPClient` inherits the new health method and its `call_utility_async` override gathers replies from every engine. One unresponsive engine may fail that frontend's `/health` without identifying the engine. Service-wide failure may be intentional, especially for coupled ranks; the open questions are attribution and restart scope. Neither DP mode was exercised.
- Review the default-on cost and concurrency boundary **in #36451 itself**. With a 60-second default, every multiprocess `/health` call adds an EngineCore utility round trip. There is no single-flight limit in the PR; each probe during a stall creates a pending utility future until a reply or other cleanup. Measure memory/queue behavior under repeated probes and timestamp a late reply in a future run.
- The reintroduced `VLLM_RPC_TIMEOUT` type and environment entry should be reviewed during rebase. [#44128](https://github.com/vllm-project/vllm/pull/44128) removed it as a dead setting; the health-ping path does not consume it. The port omitted it for that reason. [F21HGG already raised this cleanup point](https://github.com/vllm-project/vllm/pull/36451#issuecomment-5450475299) in the upstream thread; it is not a new finding from this experiment.
- Decide whether `EngineDeadError` is an appropriate type for a recoverable stall, and whether a 60-second server deadline is compatible with the intended external probe timeout.

The public-facing claim remains **EngineCore loop-liveness**, not token progress or self-healing. No upstream comment or PR change was made by this experiment.
