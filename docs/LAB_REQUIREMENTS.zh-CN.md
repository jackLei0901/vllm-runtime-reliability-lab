# Lab 需求：先有外部用途，再扩建

状态：2026-09-28 本地提案，未批准、未发布；本中文版为准，[English](LAB_REQUIREMENTS.md) 是译文。不改变 v0.2、历史评分或 Q4 预注册规则。

## 需求与现状

vLLM/PyTorch 维护者和故障排查者需要判断：卡顿或失败的运行时观察究竟证明了什么、**没有**证明什么、下一步该检查或测试哪里。现有日志、指标、profiler 和 Flight Recorder 是比较基线。只有当 Lab 的有界证据或判断规则，比普通复现评论更进一步地改变外部诊断、测试或修复评估时，Lab 才产生独立价值。

外部**交付**已经存在：[#52178](https://github.com/vllm-project/vllm/pull/52178) 带有 base/fix 退出证据，[#36451](https://github.com/vllm-project/vllm/pull/36451#issuecomment-5844585790) 收到了 Lab 证据支持的验证评论，[#197232](https://github.com/pytorch/pytorch/pull/197232) 链接了 Lab 调查。第一和第三项是自己的 PR；只有 #36451 是别人发起的线程。这些是上游产出，不等于已有非作者独立使用 Lab 产物的证据。分别记录**已交付**（我们能控制）与**被采用**（由他人决定）；没有回复记为 `not_observed`，不等于拒绝。

## 下一项工作的需求

| ID | 要求与检查方法 |
| --- | --- |
| R1 外部使用者 | 在*交付型工作*开始前，写明由他人发起的活跃线程或同意参与的事故负责人、其要做的判断及可使用的产物。允许短时架构走读先行，但未绑定使用者前只能留作私有学习，不算 Lab 产品建设。 |
| R2 流程成本 | 先定总预算，并单列探针、校验器、schema 和协议文档的时间。接近总预算的 25% 时暂停并说明新增工具究竟支持哪个判断；这是复核触发点，不是省略必要正确性测试的借口。 |
| R3 预测核对 | 预注册成功条件或预订 GPU 前，给每项关键预测附源码、已合并 PR 或受控测量依据；未核实假设单列。 |
| R4 结果闭合 | `pass`、`fail`、`unscored` 互不重叠且覆盖所有结果；冻结前写一个本应失败的例子并检验它不会通过。装置失败只能记 `unscored`。 |
| R5 决策边界 | 新分类规则在读真实案例前，用夹具覆盖每条分支，包括下游未观察与生产者冲突；不得为了满足此项凭空增加分类器。 |
| R6 证据等级 | 每项主张标明观察输出、报告叙述、源码推断或假设，并写出边界与可能反例。 |
| R7 契约分离 | 列出检查的输入和它负责的单一契约；不把退出传播或关闭预算塞进 `derive_verdict`。 |
| R8 修订约束 | 重大规则变化先版本化，再读新数据；修订编号唯一，旧评分保留。每季度最多一次有计划的工具重设计。正确性修复必须指明缺陷，并有修复前失败的夹具；披露修复且不能静默重评。 |
| R9 不挤占 | 排期前列明有日期的上游与内核承诺，每周检查是否被 Lab 工作挤占；若发生，缩减或暂停 Lab 范围。 |
| R10 发布安全 | 发帖前核查目标项目当前的 `AGENTS.md`，按要求披露 AI 辅助；检查私有路径、凭据、未证主张和断链，发出后再读线上版本。不新开 issue；在两项现有 vLLM PR 无法运行 CI 时不提交第四项；不在既定计划外 @ 维护者，也不请求 `ready` 标签。 |

## 价值检验与停损

在决定性验证或公开草稿前，先固定简短对照：该线程要做什么决定、普通复现能证明什么、Lab 产物预计多提供哪项事实或规则，以及哪种结果会**否定**这项增量主张。事后只按这份记录判断，不能临时发明对照。交付最小可运行复现、测试、验证或 review 说明，并附负对照和明确的 `unknown` 情况。如果普通复现评论也能完全支持同一决定，不把增量价值归给 Lab。现有进展、退出传播和关闭预算检查保持分离，不建统一 verdict 层。

最迟 **2026-10-12** 指定第一项符合要求的候选和使用者；若没有合格候选，就不再开展新的 Lab 建设，并于 **2026-11-01** 前转入维护模式。在 **10 月 26 日至 11 月 1 日** 的复核中，记录候选、已冻结的增量对照、第一份产物的交付状态、流程成本与受保护的上游/内核工作，不能等到月底才首次评估。

到 **2026-11-30**，争取在**由他人发起且有人活跃的运行时/生命周期线程**中**新交付**三份这样的产物；只有非作者无需追问缺失文件即可阅读或运行时才计为交付。这个目标刻意比支持自己的 PR 更难，而此领域的 review 可能较慢；两项风险都如实保留。另行记录非作者引用、复算、追问或在修复中使用的具体行动。交付是可控目标，采用是需评估的外部结果，不能事后编造。若无采用，区分线程不活跃与活跃线程认为产物无用；反复交付而无人实际受益时，转入维护模式，不再写框架提案。十小时边界审计未发现问题，只停止该次审计，不判整个 Lab 失败。

量化 GEMM dispatch 属于独立的内核正确性线。M1–M6 保留为证据索引，不作为通用 issue 分类器。40 条样本的范围门槛失败只适用于固定、关键词限定的抽样框，既不证明也不否定 Lab 的外部价值。
