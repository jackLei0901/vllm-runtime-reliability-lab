# When `/health` is green but inference has stopped

I released
[vLLM Runtime Reliability Lab v0.2.0](https://github.com/jackLei0901/vllm-runtime-reliability-lab/releases/tag/v0.2.0),
an evidence lab for inference failures where the service process remains alive
but useful work stops.

The release packages an independent base/fix validation of reported
[vLLM #53859](https://github.com/vllm-project/vllm/issues/53859) and proposed
[PR #53883](https://github.com/vllm-project/vllm/pull/53883):

- the EngineCore process remained alive;
- `/health` continued returning 2xx;
- token progress stopped under deterministic KV-event queue backpressure;
- an external stack placed EngineCore in
  `ZmqEventPublisher.publish -> Queue.put`; and
- the fix arm preserved token progress under the same trigger, while dropping
  four event batches.

This was not a lab-originated bug. The lab's contribution was to turn the
reported symptom and proposed fix into a bounded, reproducible evidence chain,
including the liveness benefit and the event-loss trade-off.

You can replay the published evidence without a GPU, vLLM, or PyTorch:

```bash
git clone --branch v0.2.0 https://github.com/jackLei0901/vllm-runtime-reliability-lab.git
cd vllm-runtime-reliability-lab
python -m pip install .
vllm-dfx replay results/vllm-zmq-backpressure-stage1-r3-20260916
```

The replay verifies the closed file set, SHA-256 identities, four-cell
base/fix contract, health and progress observations, blocking-stack claim, and
measured trade-off. It verifies archived evidence; it does not rerun the GPU
experiment or claim production readiness.

Useful feedback is concrete: the command, platform, outcome, and any unclear or
failing step. A replay report can be filed with the
[structured template](https://github.com/jackLei0901/vllm-runtime-reliability-lab/issues/new?template=replay-report.yml).
This is a request to challenge a falsifiable artifact, not a request for stars.
