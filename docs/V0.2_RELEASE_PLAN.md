# v0.2 release plan

Working title: **v0.2 — Cross-process evidence and no-progress validation**

This release packages the strongest completed results into something a new
reader can understand and replay. It does not add more issue targets.

The v0.2 scope is frozen. PyStack, NCCL RAS, DCGM, a generic producer adapter
framework, native-state classification, and new C++ probes are post-v0.2
experiments, not release blockers.

## Evidence-first boundary

v0.2 is not valuable because it collects several signals. Its claim is that a
closed verdict can be recomputed from specifically required evidence and must
remain undetermined when that evidence is absent or contradictory.

- Every public field is declared decisional or belongs to a closed
  non-decisional set for schema, integrity, and provenance.
- Changing non-decisional provenance in an otherwise schema- and
  integrity-valid bundle must not change the semantic verdict. Tampering with
  an integrity digest may invalidate the bundle, but must never select a
  different verdict.
- A producer reports a normalized observation and typed outcome; it cannot set
  the final verdict or require a tool-specific verifier branch.
- Producer kind is decisional where the contract explicitly uses it to select
  scope: `server_counter` is service-scoped and `client_request` is
  request-scoped. Producer implementation and tool identity are
  non-decisional and must never be read by verdict logic.
- Producer failure, target absence, and negative evidence remain distinct.
- New telemetry that only improves display does not enter the release schema.
- Mature external collectors are preferred over reimplementation, but none is
  a required runtime dependency for v0.2.

## Release payload

1. **Results-first front page.** Lead with PyTorch #196968, vLLM
   #53859/#53883, and PyTorch #196996 before recorder architecture.
2. **CPU-only published-result replay.** Ship the pinned #53859 four-cell
   manifest and `vllm-dfx replay ...` verifier. State explicitly that it
   verifies archived evidence and does not rerun the GPU experiment.
3. **Cross-process evidence contract.** Document `producer_missing` separately
   from `member_missing`, preserve source/file identity, and keep verification
   fail-closed.
4. **No-progress validation result.** Publish the base/fix controls, the
   health-green base stall, the blocking stack, fix-arm progress, and four
   dropped event batches as one bounded claim.
5. **Flight Recorder case study.** Include it only after #197232 receives an
   explicit upstream outcome as defined below.
6. **Known boundaries.** Preserve the distinction between shipped recorder
   capabilities, experiment-specific harnesses, archived replay, and planned
   general-purpose correlation.

- v0.2 release notes linking immutable tag URLs, not `main`;

- case-study permalink if its upstream gate is satisfied.

## #197232 publication gate

The Flight Recorder draft becomes a published case study only after one of
these outcomes is public:

- the PR is merged;
- a maintainer explicitly accepts the design but requests a different landing
  path; or
- a maintainer explicitly rejects or supersedes the design with a documented
  reason.

An open PR, passing CI, bot labels, or absence of response is not an upstream
outcome. If the rest of v0.2 is ready first, release v0.2 without the case study
and add it in v0.2.1 after the gate closes.

## Release acceptance checklist

- [ ] `python -m unittest discover -s tests -v` passes from a clean checkout.
- [ ] `python -m compileall -q src tests` passes.
- [ ] `ruff check .` passes.
- [ ] The replay succeeds without CUDA, PyTorch, vLLM, or network access.
- [ ] `pyproject.toml`, installed package metadata, the tag, and release title
      report the same v0.2 version; no artifact still reports `0.1.0a4`.
- [ ] Mutating any replayed JSON byte produces a non-zero exit.
- [ ] No README sentence describes #49869 as a lab finding.
- [ ] #53859 is described as independent validation, not lab discovery.
- [ ] #52178 is described as system-level validation of an independently found bug.
- [ ] Current upstream states are rechecked on release day.
- [ ] The release does not claim a general-purpose joiner or production monitor.
- [ ] Every public evidence field is classified as decisional or belongs to the
      declared non-decisional set; no decorative field remains.
- [ ] Schema-valid non-decisional provenance variants preserve the recomputed
      semantic verdict; digest tampering produces validation failure rather
      than a different verdict.
- [ ] Each positive verdict has at least one contradiction or
      insufficient-evidence test.
- [ ] The replay command in the README is character-identical to the launch
      post command and has been run from a clean install of the tagged wheel.

## Success after release

The primary signal is reuse: two external people run the replay, and at least
one external issue or contribution improves the evidence format or usability.
Ten genuine external stars and one fork are secondary distribution signals, not
technical acceptance criteria.
