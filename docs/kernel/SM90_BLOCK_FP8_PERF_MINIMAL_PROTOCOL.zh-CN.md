# SM90 block-FP8 分派变体：最小决定性协议

状态：2026-10-01，审阅稿 r6（一次联网核验，后续离线收据）；待公开冻结；不是开卡授权。以中文版为准；[English](SM90_BLOCK_FP8_PERF_MINIMAL_PROTOCOL.md) 为译文。本协议**取代**[章程](SM90_BLOCK_FP8_PERF_CHARTER.zh-CN.md)中的会话 A/B 计划与未发布的恢复计划。这些文档、冻结 `2c32e134…` 及 2026-10-01 的记录作为历史保持不变。

## 1. 本次会话服务的决定

> 一行分派修改（对所有 M ≤ 64 使用 `swap_ab`）是否正确，并且在强制 CUTLASS serving 实际执行的 decode 规模上可测地更快，从而值得向上游提出？

以下每一项都是因为这个决定需要它才存在。不影响该决定的内容一律删除。

**结论范围：**
- 仅限 SM90、强制 CUTLASS 回退路径和 Qwen3-8B-FP8 的四个形状。
- 正面结果支持的是**针对强制 CUTLASS 回退路径的 kernel 优化提议**，不是默认 serving 中已证明的端到端改善。默认路径在 Hopper 上选择 FlashInfer/DeepGEMM。

**已有证据，本次不重复推导：** [#44572](https://github.com/vllm-project/vllm/pull/44572) 报告，在 (4096, 7168)、小的奇数 M 上，交换路径约 17–18 µs，padding 路径约 50 µs。本次测量 #44572 未覆盖的 M % 4 = 0 的点。

## 2. 保留与删除

**沿用冻结包，不作修改：**
- patch；
- 四个形状与 20 个 M 值；
- 176 个正确性用例；
- 轮换权重的 CUDA graph 计时、A-A 校准与 ABBA 配对；
- 常数 W、R、n、b、q、k、e_rel、e_abs 与时钟规则；
- 单元格级判定（`positive` / `negative` / `below_positive_gate`）；
- M = 64 的分派身份探测。

**删除，因为决定不依赖它们：**
- capture-op → replay-node 映射及其人工复核；
- 基于 grid 的形状归属；
- V1 runner；
- 作为前置条件的 M = 63/64 差距门槛，因为变体被直接测试；
- 热/冷对照；
- 默认后端 trace；
- 拆分预约；
- 端到端估算（Amdahl）及 kernel 时间占比。

## 3. 证据与通过规则（开卡前冻结）

### E1 正确性（必需）

已定义的 176 个臂用例必须全部通过。
- base 全部通过、仅变体出现不匹配：结论为**不值得提出**（变体不正确）。
- 其他任何失败或未评分：本次会话记为 `unscored`。

### E2 分派身份（必需）

M = 64 时，`identity_probe.py` 加 `trace_tools.validate_dispatch` 须显示每臂三次启动：base 为 cooperative，变体为 ping-pong。否则会话记为 `unscored`。

### E3 配对计时（决定性证据）

以单会话模式运行 `timing.py`：
- 对全部 80 个 cell 做新的 A-A 校准；
- 对全部 80 个 cell 做 base/变体配对；
- 使用冻结的判定界与 q-of-b 规则。

**前置条件：** E3 只在构建、serving 和 profiling 全部停止后开始。开始前检查并记入 receipt：
- 没有编译进程；
- 没有 serving 进程组；
- GPU 上没有计算进程，在计时工具初始化 CUDA **之前**检查；
- 恰好一个 GPU 的 memory.used ≤ 128 MiB。仅 PID 清单为空不够，PID/显存清单不可读时关闭门槛。

在最初五分钟身份预检中运行相同的无 CUDA context 空闲检查，尽早发现容器 PID/清单问题。
E3 超时，或前三个 cell 的耗时投影超出固定窗口剩余时间，均为 `insufficient_evidence`，
保留部分记录并停止，不重试。投影只是保守成本估计，不是实测否定结论。

**单元格判定沿用现有评分**（base 为左臂，变体为右臂）：
- `positive`：差值按 q-of-b 规则超过判定界，即**已证明改善**；
- `negative`：配对差中位数低于 −判定界，即**退化**；
- `below_positive_gate`：**未证明改善**。它不表示已证明等价；
- `unscored`：校准失败或有效块不足。

**单元格分组：**
- **被改变的服务 M：** {4, 8, 16, 24, 32, 40, 48, 56, 64}，共 9 × 4 = 36 个 cell；
- **对照：** 其余 11 个 M（变体未改变代码路径，含服务 M 1 和 2），共 44 个 cell。

**决定规则（按顺序应用，CPU 测试覆盖每个分支）：**

1. **完整性。** 若 80 个 A-A 记录与 80 个配对记录中有任何缺失或 `unscored`，结论为**证据不足**。
2. **对照。** 若任何对照 cell 的 |配对差中位数| 超过其判定界，结论为**证据不足**。未改变的路径出现差异说明测量装置有问题，不是变体的性质。
3. **退化。** 若任何被改变的 cell 为 `negative`，结论为**不值得提出**。
4. **改善。** 一个被改变的服务 M 计为"改善"，当且仅当 4 个形状中至少 3 个在该 M 上为 `positive`。
   - 至少 7 个（共 9 个）这样的 M 为改善：结论为**值得提出**；
   - 否则为**不值得提出**。

**规则说明：**
- 采用"按 M 计数"的形式：问题是变体是否在实际执行的 decode 规模上普遍有效，并容许一个形状不受益。
- 7/9 与 3/4 是事先选定的工程验收规则，**不是**统计置信度声明。
- **不值得提出**的含义是：在完整、对照通过的测量中，未在冻结判定界下证明足够的改善，或出现退化。它不表示两臂等价。

### E4 serving 执行路径（辅助，仅定性）

在默认 runner（V2）下，对强制 CUTLASS serving 采集一次 Nsight Systems trace：
- 使用 `--cuda-graph-trace=node`；
- 并发为 1、16、63、64；
- 固定工作负载不变（输入 128、输出 64 token，固定 token ID，忽略 EOS）。

E4 只确立执行路径和启动次数。在每个并发级别的至少 10 个稳定 decode step 中，仅基于 replay 的见证需满足：
- **启动次数：** 每 step 恰有 144 个 `cutlass_3x_gemm_fp8_blockwise` kernel；
- **kernel 类：** 并发 1 时全部为 ping-pong 类，16、63、64 时全部为 cooperative 类。

**step 与级别的定义：**
- 一个 step 是一次 decode graph 启动，通过 CUDA API 关联确定；
- 级别按采集器记录的批次时间窗口分配；
- 任何归属不明确都使该级别记为未见证。

**padding 佐证：** 记录启动后解析的配置（`cudagraph_capture_sizes`、graph 模式），并要求：
- 63 不在 capture 尺寸中；
- 不小于 63 的最小 capture 尺寸为 64。

并发 63 时出现 cooperative 类，只确立 M % 4 = 0 的分派路径。若该 step 确有 63 个 decode token，解析配置预期 padding 至 64；trace 确认 cooperative 路径，但没有直接测量实际 M。客户端并发不保证引擎内的批大小，因此不把并发 63 当作精确 M = 64 的运行证明。

**E4 不做的事：**
- 不用 grid 推断形状或 tile 数：persistent scheduler 下 grid 不等于逻辑 tile 数，且两个形状的 N 同为 4096；
- 不计算时间占比或端到端估算：构建与 E4 并发运行，kernel 时长不作定量使用。

若 E4 失败或时间不够，E3 仍作为 kernel 级结果成立，但 serving 执行路径记为未见证。

## 4. 工具修改（CPU 侧，最多 3 个工作小时）

原冻结包不实现本协议。独立后继包 [`sm90-block-fp8-perf-minimal`](../../experiments/kernel-operand-contracts/sm90-block-fp8-perf-minimal/README.md) 已实现以下修改；原目录的工具与清单不变。CPU 测试覆盖判定与解析器，并不证明 GPU 执行成功。公开冻结前核对测试结果和后继清单。

### 4.1 `timing.py` 单会话入口

- 新增 `--session S`，现有 A/B 行为不变。
  - 计划与 B 相同：80 个 A-A 加 80 个变体配对。
  - 需要：base、variant、dispatch（`witnessed`，两臂构建）、correctness（176 全部通过，同一 GPU）。
  - 不需要 `--session-a` 与 `--workload`。
- E3 前置条件检查写入结果。
- 第 3 节决定规则实现为纯函数，输出：
  - `worth_proposing`、`not_worth_proposing` 或 `insufficient_evidence`；
  - 每个被改变的 M 的形状计数。
- 结果中把 `below_positive_gate` 的含义写明为"未证明改善"。

### 4.2 聚合测试（CPU）

用合成记录覆盖：
- 7/9 与 6/9 的边界；
- 3/4 与 2/4 的边界；
- 缺失 cell 与 `unscored` cell；
- 对照失败（两个方向）；
- 被改变 cell 的退化；
- 一个区分"按 M"与"按形状"两种形式的用例。例如每个 M 都有 3 个形状改善，但缺失的形状轮换：按 M 为值得提出，按形状则不满足。

现有 A/B 测试保持通过。

### 4.3 E4 检查器与采集设置

- **检查器：** 小型、仅基于 replay，作用于导出的 SQLite。
  - 按 graph 启动关联划分 step；
  - 按采集器记录的批次窗口分配级别；
  - 按 kernel 名称子串（`Cooperative` / `Pingpong`）分类；
  - 统计每 step 启动次数；
  - 检查解析配置中的 capture 尺寸；
  - 归属不明确时失败关闭（fail closed）。固定检查每级别前 10 个可归属的 decode graph 启动，不挑选成功步骤。
  - CPU 测试基于现有 V2 导出的表结构编写；这些数据只作解析器开发输入，不重新评分。
- **serving 启动设置：**
  - 仅在 localhost 上设 `VLLM_SERVER_DEV_MODE=1`；
  - 把 serving 环境的 `bin` 目录加入 PATH；
  - 强制 CUTLASS 的环境变量；
  - 采集器记录每个批次的 UTC 与 monotonic 时间窗口；导出 SQLite 使用 UTC normalize，时钟跨度差超过 50 ms 时拒绝归属；
  - 以上全部写入 receipt。

### 4.4 冻结

- 新建后继冻结清单，引用本协议和修改后的工具摘要。
- `2c32e134…` 的冻结清单不编辑，原工具在该 commit 处保持可复现，原目录也不编辑。

不构建其他任何东西。若这些修改超过 3 小时，就停下重新考虑，而不是延长。

## 5. 一次会话，最多 90 分钟

| 步骤 | 上限 | 说明 |
| --- | ---: | --- |
| 身份、PATH、ninja、磁盘 | 5 | 复用现有环境与模型；记录 GPU UUID |
| 构建 base 与变体，仅内存门槛通过时并行 E4 | 35 | E4 只确立执行路径与启动次数；kernel 时长不作定量使用 |
| E2 分派探测 | 5 | |
| E1 正确性 | 10 | |
| E3 前置条件检查与配对计时 | 20 | 构建、serving、profiling 全部停止后开始；160 个记录 × 392 次 replay |
| 封存、下载、核验、关机 | 10 | 在控制台确认停止计费 |

两条规则：
- **剩余时间不足以覆盖某步上限时，不开始该步。**
- **超时**的剩余项目记为未评分；若涉及 E3，结论为证据不足。

**预算核算：** 2026-10-01 会话已用 38 分钟 H800 时间。本次 90 分钟使性能项目的 GPU 时间合计最多 128 分钟。开卡前报告迄今已用工作小时与 18 小时预算的对比。历史精确耗时为 38 分 15 秒，总上限为 128 分 15 秒；“128 分钟”为取整值。

两臂构建**顺序执行** base→variant，由 `build_pair.py` 固定一个 2,100 秒 UTC 截止时间。
每次编译子进程上限为 min(1,200 秒，共享截止时间的剩余秒数)，第二臂不重置窗口；
base 失败不启动 variant。身份预检记录物理/cgroup 内存，构建要求已知可用内存 ≥32 GiB。
只有有效内存上限 ≥96 GiB 且可用内存 ≥64 GiB 才允许 E4 与构建并行；collector 在启动前复验。
不满足时跳过 E4，记 unwitnessed。保守快照不保证编译峰值内存，不作更改参数后的重试。

E2 前在构建结束或共享截止时间到达时（取先发生者）结束 E4。仍在运行时，仅终止
核实归属的 collector/server 进程组，SIGTERM 清理最多 10 秒，随后 SIGKILL 剩余
本次进程组；不等待采集或 profiler flush 自然完成。保留部分收据，中断 E4 记 unwitnessed。
E2、E1 前分别运行 `apparatus.py --idle-only`，无 CUDA context 空闲检查通过才开始。
清理耗时计入现有上限，不增加预算。E4 的 `replay_check.py`/SQLite export 延至 E3 后
且有剩余时间时，优先关机后离线执行，使用已封存并核验 digest 的 report。
不完整或中断的 E4 不升级为 witnessed；E4 导出/复核不与 E2/E1/E3 重叠。

## 6. 停止规则

仅在最初五分钟、启用已核查的学术加速/代理时，联网逐字节核对 GitHub 原始清单，
保存私有 `public_freeze.json`（commit、清单 SHA-256、URL、核验时间、成功状态）。
之后每个工具通过 `SM90_PUBLIC_FREEZE_RECEIPT` 离线核对收据与全部本地字节绑定；
缺失或不符直接拒绝，不回退联网。子进程继承该变量，E4 离线复核使用同一下载收据。
网络失败保留记录并在构建前停止。收据是可信本地来源记录，不是独立签名证明。

- **装置失败或证据不足：** 若本次会话因装置原因（构建、E1/E2 未评分、工具、E3 不完整或对照失败）未得出决定，记为 `unscored` 或 `insufficient_evidence`，并**结束本实验**，不做第三次尝试。这不是"没有差距"。
- **不值得提出：** 结束本实验。性能方向继续，但换一个新问题。
- **值得提出：** 下一步是上游对话，作为 #44572 的后续，遵守现有 PR 与 issue 约束；而不是进一步的本地研究。表述限于强制 CUTLASS 回退路径的 kernel 级改善。
