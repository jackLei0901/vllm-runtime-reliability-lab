# #52365 候选收尾

状态：2026-09-29 关闭 Lab 候选，未交付 Lab 材料。本文为准；[英文版](PR52365_SECOND_CANDIDATE_CLOSEOUT_2026-09-29.md)是翻译。此处关闭的是 Lab 候选，不是上游 PR。

[候选记录](PR52365_SECOND_CANDIDATE_2026-09-29.zh-CN.md)提出的问题是：默认开启的 60 秒 GPU 输出事件等待上界，是否会杀死合法但最终完成的步骤。[实测补充](PR52365_SECOND_CANDIDATE_ADDENDUM_A1_2026-09-29.zh-CN.md)要求测量单次等待，并比较基线、PR 默认值和 PR 关闭超时三组。[离线可行性审查](../../experiments/pr52365-event-timeout/PRE_GPU_REVIEW_2026-09-29.zh-CN.md)认为拟议的 24 GiB RTX 4090 单元缺少可信的时长余量，还可能在启动时内存不足。80 GiB H800 仅通过粗略的容量筛选；单步等待时长、激活内存能否容纳和负载代表性均未实测。两种配置都没有运行。曾打开的 4090 实例未运行 vLLM 单元即已下达关机命令；云控制台计费状态未核实，也不属于实验依据。

| 已观察结果 | 未运行服务、未测量单次事件等待、未做三组对照。`supported`、`not_reproduced` 与运行时 `no_candidate` 均为**未评分**，不是反例。 |

| 流程成本 | 工具和审查用时未可靠记录，不能计算 R2 比例。这是流程记录缺口，不代表成本很低。runner、hook、测试及补充方案均未用于运行。 |

源码审查只支持更窄的问题：PR 使先前没有读取点的 60 秒设置默认生效；复制事件可能包含尚未完成的前向计算。它**不能**证明真实合法步骤的等待超过 60 秒。4090／H800 算术只是开卡筛选，不是时延测量或对 PR 的判决。

本次收尾不触发 GPU 预约、继续开发 runner、上游发帖或 @ 维护者。只有出现自然慢但成功的单次事件等待实测，或作者／reviewer 明确要求缺失的负控，才重新立项，并须先冻结新的有界方案。否则源码笔记仅留作 Q5 review 素材。下一个 Lab 候选是 [#54553](PR54553_THIRD_CANDIDATE_2026-09-29.zh-CN.md)，仍受其自身预检门槛约束。
