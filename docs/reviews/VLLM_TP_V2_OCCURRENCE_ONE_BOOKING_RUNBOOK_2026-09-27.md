## Order within the single booking

1. **Read-only host preflight.** Confirm exactly two visible GPUs, working CUDA driver/toolkit (`nvcc`, `cuda.h`, `libcudart.so`), `g++`, `make`, sufficient model/disk space, the pinned vLLM/Torch installation, model checkpoint, and the inherited NCCL library. Record versions and file digests privately. The [pinned Inspector Makefile](https://github.com/NVIDIA/nccl/blob/v2.29.7-1/plugins/profiler/inspector/Makefile) needs CUDA development files even though the build itself does not use a GPU. **Post-run amendment for any future booking:** after selecting the exact serving venv, also require `command -v ninja` with that venv's `bin` on `PATH`. This amendment was not part of the original run's preflight and does not change its score.
2. **Patch/build, no engine yet.** In a fresh NCCL checkout at the tag/commit, run `git apply --check` against the transferred patch, apply it, run `git diff --check`, then `make` in `plugins/profiler/inspector` with the actual `CUDA_HOME`. Hash the new `.so` and verify the `LLR_TP_EVT_V2` marker is present. Do not overwrite the old Inspector binary. Failure is an apparatus result; stop before loading vLLM.
3. **Load smoke.** Use a fresh owner-only private directory. Confirm the patched `.so` loads in exactly two rank-bound NCCL logs and each worker has a distinct PID/start-time identity plus a V2 graph-manager witness. Resolve `/proc/<pid>/maps` for both workers and hash the single NCCL shared library actually loaded. If the binary, library, rank binding, or witness is ambiguous, stop unscored.
4. **Healthy control.** In another fresh private directory, run `serving_v2_stall_gate.py --mode control --model <pinned-model-path> --private-dir <control-dir>` under an external 180-second timeout. Set the exact environment required by `_check_environment`, including `NCCL_PROFILER_PLUGIN`, `PYTHONPATH` for the plugin entry point, `LLR_TP_HOLD_SECONDS=3`, `VLLM_PLUGINS=llr_tp_v2_stall`, and the NCCL debug/Inspector paths pointing inside that cell's directory. Leave `VLLM_USE_V2_MODEL_RUNNER` unset. Require `healthy_v2_full_replay_observed`, valid callback history, 16 tokens, and the one-use receipt. Anything else is a hard stop before hold.
5. **One hold, only after control passes.** With a third fresh private directory and identical source/build identities, run `--mode hold --control-receipt <control-dir>/control-receipt.json` under the same external timeout. It arms rank 1 for one bounded 2–5-second pre-replay hold. Do not retry or retune live. Preserve `before`, `during`, `after`, the receipt, rank logs, witnesses and environment manifest privately; publish only closed-shape results and digests. Stop and shut down the cloud instance after capture and a bounded integrity check, regardless of score.

## Decision table

| First failed or successful gate | Recorded result | What it means; next action |
| --- | --- | --- |
| Patch application or Linux compilation fails | Build/preflight failure, no serving score | The apparatus is not ready. Fix offline, then preregister a new booking; do not infer an NCCL observability gap. |
| `.so` loads incompletely, two ranks cannot be bound, or runtime NCCL mapping is ambiguous | `unscored` preflight | Identity/provenance is missing. Stop before the control or hold; no rank-level claim. |
| Healthy control fails callback ancestry, exact descriptors, or cross-rank occurrence checks | `unscored / callback_history_invalid` | The occurrence contract or producer is inadequate even without a fault. This is a hard stop before hold and an actionable apparatus finding, not evidence of a serving fault. |
| Healthy control lacks observed-window cached-FULL replay or complete output | `unscored / control_precondition_failed` or another typed reason | The intended route was not exercised. Do not use a hold result to compensate. |
| Control passes, but hold marker/window/release or identity cannot be proved | `unscored` with the runner's exact reason | No valid in-flight comparison; do not call it a negative producer result. |
| Control passes; during hold exactly one occurrence has rank-0 `KernelChStart` ahead of rank 1, descriptors agree, and rank 1 catches up after release | `start_asymmetry_observed` | One-run positive result: the **Lab-local patched Inspector acquires** an in-flight, rank-specific channel-start fact during controlled V2 serving. It does not prove completion, organic hang diagnosis, or stock Inspector export. Next gate: compare stock export for that same occurrence. |
| Hold is valid but no unique target, or ranks/descriptors disagree after release | `unscored / target_collective_ambiguous`, `rank_occurrence_mismatch`, `rank_descriptor_mismatch`, or `rank_did_not_catch_up` | The planned discrimination was not established. Retain the exact snapshots for offline diagnosis; do not select a favourable callback or run a second hold in this booking. |
| Secondary 16 × 74 / first-decode prediction differs while the primary score is valid | Keep primary score; prediction mismatch is non-scoring | Recheck the source-to-step map later. The prediction cannot upgrade or invalidate the observed callback asymmetry. |
