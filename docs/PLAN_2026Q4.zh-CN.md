## 本季度主线：顺序完成证据循环

让 Lab 形成持续的 **故障复现 → 有界判断 → 负对照 → 公开重放 →
upstream exit** 能力，而不是继续增加 collector。先收口 #53859
完整案例和 EngineCore health ping 的正常长步骤边界；10 月末按已登记的
痛点评议结果，决定是否启动一个不重叠的下一 PoC。同一时间只运行
一个 PoC；若没有证据足够的候选，记录 `no_candidate`，不靠开新
issue 填补时间表。

以 #53859 为真实阻塞正例，Lab 已对 [#36451](https://github.com/vllm-project/vllm/pull/36451)
的 DP=1 Python health-ping 路径在当前 wheel 上完成一次四 cell 对照，并把有界结果
[评论到 #36451](https://github.com/vllm-project/vllm/pull/36451#issuecomment-5844585790)。
这是 **source-equivalent** 证据，不是精确 PR-head、DP>1 或长步骤
误报验证。首选 upstream exit 已发生；验证旧 head `206f28d` 与其
不兼容依赖不再是默认的季度目标。只有出现可构建的 rebased head 且
精确验证会改变上游决策，才重开该门槛。不再为同一机制另提健康检查方案。
只有找到已证实的
“loop 回应 ping、却有需求且无进展”案例，才重新考虑独立进展信号。
这不是自动重启/自愈产品计划。

`v0.2.0`、#53859 的无 GPU replay 和 `collect/verify` 已交付，不
再列为未来发布目标。#196968 完整 case study 仍须等待 #197232

## 持续发现：输入而不是 issue 数量

每周给发现工作固定的小时间盒（建议约半天），来源为：既有 issue
抽样、别人 PR 的审阅/复现、CI flake、Lab 负结果及社区反馈。
源码边界审查同样是入口，不能只靠被报告的问题。发现记入**私有、
去重**的痛点台账，不立即建立新故障类别，也不自动向 upstream
开帖。每月最后一周评议最多三个候选，只允许一个进入下一轮 PoC。

台账最小字段：症状、原始来源与固定时间点、受影响边界、被误导或
缺失的信号、证据等级（同次运行材料／源码加复现／报告者叙述／未知）、
现有诊断方法或 PR、下一项区分实验、重复归并键、隐私等级、状态及
放弃原因。`owner` 可记录活跃审阅者作为路由线索，不能拿
CODEOWNERS 推断某人已同意方案。

现有 40-issue 协议只估计已报告 runtime-reliability 问题中的
V1–V3 taxonomy 覆盖。痛点字段是描述性附栏，不能把报告中未提
某工具推断成该工具漏检。维护者追问次数与到根因时间只作背景：
未解决项的根因时间是未知/删失，不计零；关闭不等于查明根因。
另单列“loop-level ping 是否可能发现”：是／否／未知，作为源码
或报告支持的描述性判断，不从沉默推定为否。样本频率也不是生产
事故发生率。

## 停损与外部结果

- 每次 PoC 在开工前写明可能的 upstream exit；允许 `no upstream
  action`。Lab 自身结论必须达到严格证据门槛，上游沟通只提与对方
  当前决定直接有关、可复现的事实。
- DP=2/G1 默认不租卡。只在 CPU 身份矩阵通过、且确实需要区分
  “一个 engine 持平而另一个增长”时运行；不是为了重证映射。
- 自动 recorder 触发器本季度默认 NO-GO；不能绕过新鲜度、需求、
  PID identity、scope、冲突及负对照，或改写已冻结 v0.2 语义。
- 30 秒检测、零误报、长生成 token 数都不是预定成功阈值。
  先按目标版本、上下文长度、负载与可接受误报代价冻结阈值；
  有限次运行只能报告“观察到的误报次数”，不能证明误报率为零。
- 若门槛晚两周仍未过，缩小或取消对应 PoC，日期不自动顺延。
  不以新 collector、新 issue 或冷私信填补进度。

争取但不计作可控完成的外部结果：Lab 证据被 upstream 采用、
非作者 replay、外部 issue/PR、maintainer 主动咨询和真实 stars。
技术价值优先于这些传播数字。#49869 不属于 Lab 发现；
#55547 由独立对话处理，不计入本季度计划。
