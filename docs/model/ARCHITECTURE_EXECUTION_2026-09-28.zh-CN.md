## 阶段目标与基线

让 [M1–M6 运行时模型](RUNTIME_MODEL.zh-CN.md)实际指导一次完整的“问题发现 → 证据定位 → 可复核结论 → 下一项工作选择”循环。月底的验收不是写了多少模型代码，而是能否从模型和索引找到证据、指出缺口，并据此接受一个 PoC 或明确记为 `no_candidate`。

截至 9/28：M1–M6 `0.1.0`、[索引](../INDEX.zh-CN.md)、实验状态头及其测试已存在；候选 ID 快照已封存为 823 个编号，但尚未读取候选正文或产生 40 个标签。`src/dfxlab` 尚不消费模型；v0.2 verdict、外部 schema、历史分数均保持不变。架构分支为 `lab/runtime-model`，不把它写成已合入 `main`。

## 10/26–11/1 预设评议门槛

**基线与计时：**本节在读取首个候选正文前固定。目前有 823 个候选编号，尚无 40 项标签、盲重标或分类耗时。自 9/28 起记录本方向投入（抽样、模型相关工具、G0 与技术文档）；此前未计时的工作单列为 `unmeasured_prior_work`，不伪称零小时。既有 #53859 PoC、Q5 upstream 审阅与 Q6 kernel 工作另计，避免混算。为每个审读项私下记录打开正文至完成排除/标签的主动分钟数，暂停时间不计；没有计时的项仍保留，但不补估。

| 指标 | 预设门槛和解释 |
| --- | --- |
| 同人重标一致性 | 预定前 10 个合格项的 `model_relation` 四选一至少 **8/10** 一致；`guide_issue` 在 40 个合格项中最多 **5** 条。重标是同一人的延时一致性，不冒充独立标注者。 |
| 模型范围 | 40 项中 `outside_model` 与 `insufficient_information` 合计最多 **24/40**。超出说明本模型对这次固定报告框架的解释范围有限，不等于 vLLM 总体覆盖率低。 |
| 放置成本 | 40 个合格项的主动分类时间中位数不超过 **15 分钟**；若超过 5 项缺少可信计时，成本项标为 `unscored`，不得用剩余项冒充全样本。 |
| 决策影响 | 下一个 PoC 或 `no_candidate` 的书面理由至少引用一项 M-part 计数或重复 `model_gap`，并说明该事实如何改变仅按零散 issue 选择时的判断；只提模型名称不算。 |
| 上游复用 | 相关的 Q5 lifecycle PR 审阅若确实受益，可以引用有证据的模型事实并记录；没有合适审阅对象时不强行引用，也不把维护者答复作为门槛。 |

**继续：**完整 40 项与按时盲重标可评分，前四项均达标，至 11/1 本方向新记录投入不超过 **45 小时**，且 Q6 的 #55537 交付未因本方向挤占而延误。继续也仅表示可考虑下一项有失败测试的 PoC，不批准自动扩展 `src/dfxlab`。

**修订/转向：**一致性为 **6–7/10**，或 `guide_issue` 超过 5 条，或范围、成本、决策影响任一未达标时，不启动新模型代码；保留原始标签与版本，在评议中决定收窄模型、改善指南的下一版本，或退回证据索引。不得在当前样本中途重写标签。缺计时导致的 `unscored` 也走此路径。

**暂停：**一致性 **≤5/10**，或本方向新记录投入超过 45 小时，或有记录表明 Q6 交付因本方向延误，则暂停模型扩展，写一次简短复盘，模型保留为参考。若到评议时样本/盲重标尚未完成，不计算上述 40 项门槛，不把时间不足称为 `NO-SAMPLE`；只在剩余工作可落在 45 小时上限内时批准有界收尾，否则暂停。范围超标单独触发修订，不凭一个刻意限于 liveness 的模型去宣称整个 Lab 失败。

**预演失败与复盘：**最可能的三种失败是宽关键词带来过多排除、模型标签需要源码知识才能判读，以及抽样挤占 #55537；每周分别查看审读速度、`guide_issue` 和 Q6 保留工时。月底在同一计划下记录阈值、实测、偏离原因及停止/继续决定，不另造 OKR 或仪表盘。

## 现在可以写、暂不写的代码

- **现在可写：**抽样记录的离线校验器与变异测试、G0 CPU 控制、已有 bundle/replay 的真实缺陷修复、模型索引及证据链接的一致性测试。这些工作不改变模型标签或 verdict 语义。
- **暂不写：**通用模型注册服务、新 collector、自动健康控制器、把 M1–M6 直接塞进 `progress.py`、给 v0.2 添第六个 verdict。pause/sleep 和 EngineCore loop 响应是真实输入缺口，但尚没有获准的新契约和失败测试。
- **边界：**C++/kernel 能力建设仍按 Q4 计划独立推进；不把 #55537 或 c10d 工作伪装成 Lab 的运行时模型实现。

## 最小技术文档补充

1. **生产者契约表（10/25 前）：**针对本轮实际使用的 M3/M4 信号，逐项记 owner、观测单位（请求/engine/进程）、身份绑定、时间戳与新鲜度、缺失/冲突结果、现有代码入口。先描述现状和未知，不新增 schema 字段。G0 和 ping 对照决定哪些行能够声称“可用”。抽样超出预算时只保留已核实的行，不赶写未证项。
2. **证据追溯表（10 月底评议前）：**每个实际使用的 M-ID 链接到固定版本的实验、控制、结果和剩余边界；未测项写 `unverified`。它是[架构映射](ARCHITECTURE_MAPPING_2026-09-27.md)的验证补充，不复制已有源码走读。
3. **有条件的设计说明（月底才决定）：**若选中的 PoC 需要改判定或 schema，先写版本、输入/输出、失败语义、兼容性和当前会失败的测试；若没有这样的需求，就不写新框架提案。

样本的判读规则仍以已冻结的[标注指南](../PAIN_POINT_M_PART_LABELING_GUIDE_2026Q4.zh-CN.md)为准。不得在抽样途中用新技术文档暗中改变标签定义。公开分享前单独检查隐私、提交范围和未跟踪材料。
