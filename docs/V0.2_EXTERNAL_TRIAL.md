# Five-minute external trial

This trial checks whether someone other than the lab author can install the
project, replay one published result, and produce a native process-observation
bundle. It requires no GPU, vLLM, or PyTorch. A fresh environment may need
network access to obtain the standard Python build dependencies.

It does not rerun the original GPU experiment and does not ask you to star the
repository. A failure, confusing instruction, or `undetermined` result is useful
feedback when accompanied by the command and platform.

## 1. Clean install

Use the published release tag, not the moving default branch:

```bash
git clone --branch v0.2.0 --depth 1 https://github.com/jackLei0901/vllm-runtime-reliability-lab.git
cd vllm-runtime-reliability-lab
```

From that fresh checkout:

```bash
python -m venv .venv
```

Linux or macOS:

```bash
. .venv/bin/activate
python -m pip install .
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
python -m pip install .
```

## 2. Replay the published #53859 result

```bash
vllm-dfx replay results/vllm-zmq-backpressure-stage1-r3-20260916
```

The final lines should report:

```text
PASS: /health remained 2xx while token progress stopped
FIX ARM: token progress completed under the same trigger
TRADE-OFF: 4 event batches dropped
BOUNDARY: replay verifies archived evidence; it does not rerun the GPU experiment
```

## 3. Exercise native collect and verify

Observe the current shell process while it stays alive. On Linux or macOS:

```bash
vllm-dfx collect \
  --pid $$ \
  --observation-only \
  --window 5 \
  --no-progress-window 2 \
  --sample-interval 0.5 \
  --output trial-bundle
vllm-dfx verify trial-bundle
```

On Windows PowerShell:

```powershell
vllm-dfx collect `
  --pid $PID `
  --observation-only `
  --window 5 `
  --no-progress-window 2 `
  --sample-interval 0.5 `
  --output trial-bundle
vllm-dfx verify trial-bundle
```

Both commands should report a service-scoped `undetermined` verdict. That is
intentional: PID-only observation proves that the original process identity
survived, but it has no endpoint or progress producer and therefore cannot
claim progress or no-progress.

The author's local replay or trial is a smoke check, not an external-user run.
Only a non-owner's reported command, platform, and outcome counts toward the
external-reuse target.

## 4. Report the run

Use the replay-report issue template, or send these four fields directly:

```text
OS and version:
Python version:
Exact command:
Outcome or first error:
```

Do not include a private endpoint, prompt, response content, credential, raw
stack, or complete command line from the observed service. For a failure, the
bounded `FAIL:` line is sufficient for the first report.
