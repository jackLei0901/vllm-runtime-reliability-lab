# v0.2 public field-role audit

This audit covers every scalar leaf in the expanded public shapes of
`observations.json` and `summary.json`. Nullable object containers such as a
disabled stack producer are represented by their expanded field family rather
than by a separate role for the `null` container. The machine-readable registry is
[`../schema/collect_verify_v0_2_field_roles.json`](../schema/collect_verify_v0_2_field_roles.json).

## Roles

- **Decisional:** an authoritative observation consumed by producer, demand,
  process, health, conflict, scope, or verdict logic.
- **Non-decisional:** structural, integrity, provenance, bounded explanatory,
  or corroborating data. It can make a bundle invalid or improve attribution,
  but it cannot select a different semantic verdict.

`summary.json` is never trusted as verdict input. It is a deterministic
projection of `observations.json`; the verifier recomputes it and requires exact
equality. Its stored verdict and reasons are therefore non-decisional derived
claims, not a second source of truth.

## Important boundaries

- Producer **kind** is decisional because `server_counter` and
  `client_request` select service and request scope respectively.
- Producer **implementation** is absent from the decisional shape. Adding an
  implementation field fails the closed schema, and verifier logic must never
  branch on tool identity.
- Stack state and stack-producer identity are non-decisional in v0.2. Stack
  availability cannot change the no-progress verdict.
- PID, endpoint digest, sampler identity, and request digest bind provenance or
  integrity. They do not independently establish progress.
- Collection bounds and the configured minimum duration validate the evidence
  window. Evaluation bounds are decisional because all samples are selected
  against them.
- HTTP status is retained as bounded corroboration for normalized `ok` and
  `error_kind`. The validator rejects inconsistent combinations, but a valid
  2xx status variant cannot change a verdict.

## Enforced tests

The audit is executable rather than documentary:

1. representative server/client and stack-unavailable bundles enumerate every
   scalar leaf in the expanded public shapes; disabled and unsupplied variants
   retain the same closed schema with nullable containers;
2. the enumerated set must equal the role registry exactly, with no overlap;
3. schema-valid changes to PID, endpoint digest, request digest, collection
   bounds, and 2xx status preserve the semantic verdict;
4. adding producer implementation identity fails closed;
5. changing `summary.json` or an observation digest cannot create a different
   verdict; it invalidates the bundle.

## Audit result

No v0.2 field is currently unclassified. No producer implementation identity
is present in the public contract. Future fields must update the registry and
its coverage test in the same change, or CI fails.
